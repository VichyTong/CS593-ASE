Meaningful additions and relation to measured gaps

All ten new methods are in tests/test_providers_round2.py:

1. test_cache_reuses_before_expiry_and_refreshes_at_and_after_ten_minutes
   Uses a mutable monotonic clock at 1000, 1599.99, 1600, 2199.99, and 2200.25.
   Distinct editions prove which data is returned before, exactly at, and after
   expiry. Verifies full bibliographic results, three actual mocked HTTP calls,
   identical intended query parameters, and no throttle sleep for these gaps.
   TTL correctness was missing behavioral evidence even though cache code lines
   were already covered; simply hitting a cache branch would not catch stale data.
2. test_cache_keys_separate_query_page_and_sort_results
   Four distinct query/page/sort combinations have four gold results. Revisits
   must reuse each own result without new HTTP. Verifies all fields, totals,
   response page, start offsets, terms, and sort parameters. A cache keyed only
   by topic or only by page could pass the old exact-repeat test but fail this.
3. test_throttle_waits_only_for_the_missing_interval_without_real_sleep
   Requests at virtual 1000 and 1001 cause exactly one 2.1-second mocked sleep,
   sending the second request at 1003.1. A request at 1007 needs none. Checks
   HTTP timestamps, results, and query parameters. Covers 25->26 and line 26
   while establishing timing behavior, not merely observing sleep was called.
4. test_permitted_relative_and_arxiv_redirects_return_exact_streamed_pdf
   Follows a relative arXiv redirect and a trusted export.arxiv.org redirect.
   Verifies all three destinations/options, no redirect-body iteration, exact
   final bytes including around an empty chunk, and response closing. Addresses
   line 92 / branch 90->92 and distinguishes safe following from silent refusal.
5. test_streamed_download_accepts_size_limit_and_rejects_one_extra_byte
   Real streaming loops accept exactly 20 MiB with correct length/hash and reject
   20 MiB+1 with a meaningful limit error; HTTP response closing is checked in
   both cases. Covers line 98 / branch 97->98. This is independent of the upload
   size tests: streamed download is a separate ingress path with its own bound.
6. test_failed_transfers_and_redirect_exhaustion_preserve_saved_paper_state
   Four API subcases exercise interrupted streaming, oversized streaming,
   repeated permitted redirects until exhaustion, and upstream HTTP 503.
   Every failure returns error-only JSON, keeps the original raw database row
   and complete API detail, leaves pages/PDF flags and analyses empty, and
   creates no file. Requests must use only the expected destination/options
   and responses must close. Exhaustion covers line 100 / branch 85->100.
   The interruption yields a readable PDF before transfer failure: treating the
   buffer as successful would create misleading state and fail the test. A clean
   retry must fetch again and save exact fresh bytes and source text.
7. test_malformed_and_error_feeds_are_not_cached_or_returned_as_success
   Malformed XML and a valid entry followed by an arXiv error entry must fail,
   retain an existing library paper and storage, then allow the same query to
   recover and cache only its successful result. Full returned fields/saved_id,
   requests, and call counts are checked. Covers lines 58-59 and branches 57->58
   and 58->59; also checks failure-cache behavior in already covered paths.
8. test_non_arxiv_entries_are_ignored_while_valid_unknown_fields_are_preserved
   An unrelated entry is excluded, while a valid paper with missing author,
   year, and category retains honest unknown fields and the right fallback
   total. Full results are checked. Covers line 60 / branch 58->60 with a real
   identity-validation concern, rather than accepting a junk entry as a paper.
9. test_punctuation_only_search_reports_input_error_without_http
   '!!!' meets the API's string length requirement but contains no topic terms.
   Checks an actionable error rather than successful empty results, and verifies
   no HTTP. Covers line 34 / branch 33->34; the motivation is invalid user input.
10. test_direct_unconfigured_llm_client_fails_before_http
    Missing key and missing model both raise the setup error before post. This
    complements the existing app guard, which does not call LLM.complete at all.
    Covers line 122 / branch 121->122 and verifies no chargeable attempt occurs.

Provider time is a controlled object and sleep is a Mock that advances it; the
real process monotonic clock is not replaced. Only HTTP boundaries are mocked
for service requests. Actual cache decisions, throttling, XML parsing, download
loops, LLM preconditions, API routes, PDF extraction, and storage execute.

Existing assertions improved and why

Four retained method bodies changed; evidence/retained-test-changes.diff records
the exact pre-execution edits. No expected outcome was corrected:

- Untrusted redirect rejection previously asserted only a single HTTP call.
  It now checks the original arXiv URL and disabled automatic redirect behavior.
  A single request to the wrong destination would no longer satisfy the test.
- The search-timeout test previously started with an empty library. A hypothetical
  failure that wiped the library would also leave it empty and could pass. It
  now seeds a saved paper, compares its complete detail and membership afterward,
  checks file state, and verifies the request destination/query parameters.
- The initial connection-failure test now compares the whole saved record,
  error-only response, raw SQLite pages/pdf_path/analysis state, and all upload
  entries. The old *.pdf-only assertion could miss a non-PDF orphan, and narrow
  flags could miss metadata damage. Its network destination/options are explicit.
- The quota-retry test previously checked only a history length of one after
  success. A wrong saved answer or task could pass. It now checks exact answer,
  task/model/source/coverage/warning, API/SQLite agreement, unchanged state after
  failure, and reuse of the successful result on a third request without HTTP.

These are concrete assertion blind spots found by review, not application bugs
observed or seeded in this round. No mutation test or synthetic fault injection
into application code was performed, so no mutation score is claimed.

not proof that every multi-line PDF must extract correctly.

No incorrect new fixture/expected-value pair or setup problem was identified in
review. That is an agent judgment against the README, user guidance, gold fixture
data, and explicitly described contracts, not a human-certified proof. Passing
tests alone do not establish their correctness.

For error cases, the README requires actionable errors; Papertrail's established
API convention returns PaperError as error-only JSON with HTTP 400. The tests
check that convention and meaningful error categories, rather than forwarding
external HTTP 503 or accepting generic 500 responses. This exact status policy
is a clearly stated application contract, not an arXiv service requirement.

The ten-minute and 3.1-second requirements are explicit in the README. The exact
redirect attempt count is not: the exhaustion test requires bounded failure and
uses eight as a fixture guard against hanging, without defining a new product
policy. The earlier '20 MB' unit ambiguity remains; tests explicitly use the
configured 20 MiB convention. No new date-priority or general PDF-accuracy policy
was inferred from source code to force a pass.

Quality beyond coverage and remaining limitations

This strategy added evidence about result identity, expiry boundaries, request
spacing, failed-result caching, streamed bytes, resource closing, and persisted
state. Some of its strongest changes exercise code that was already covered:
TTL/key tests and stronger timeout/quota assertions therefore improve the oracle
without needing new statements. Coverage alone cannot show those improvements.
The checks explain how plausible stale-cache, partial-save, or wrong-answer
regressions would fail, but fault-detection gains were not quantified with mutants.
The only observed defect-detection evidence remains the same three real defects.

Remaining gaps are recorded rather than filled solely to approach 100%:
- providers.py still misses line 75 / branch 74->75 (internal capacity eviction)
  and line 131 / branch 130->131 (optional reasoning setting). The README does
  not promise an eviction algorithm/capacity, and this round prioritizes failures
  affecting results and storage over a model-specific request-setting case.
- Timing tests are deterministic, single-process, and serial. They do not test
  threaded races, real scheduler delays, provider rate limits, or cache behavior
  across multiple workers. Invalid/mixed XML examples do not cover every feed
  shape, encoding, or semantic inconsistency.
- HTTP doubles simulate requests response/stream contracts; they do not prove
  behavior over real sockets, proxies, TLS, compression, or every exception type.
  Redirect host/port variants and actual maximum-hop product policy need more
  context. The finite fixture guard is not a formal termination proof.
- Some request assertions pin current timeout tuples. Those protect the current
  bounded-request contract, but legitimate timeout tuning would require updating
  the tests. Fixture use of requests.Response's content storage is also coupled
  to the pinned dependency version; neither is a universal service requirement.
- app.py remains missing statements 25, 95, 292, 304, including non-object edits,
  absent readable upload content, deletion during analysis, and server startup.
  Its six missing branch destinations remain unchanged, including arXiv metadata
  non-match handling. No server process is launched by these tests.
- pdf_tools.py remains missing statements 29 and 79, with six missing branch
  destinations for complexity, title/author edge paths, and budget skipping.
  Pathological PDF objects, Unicode normalization, disk failures, and complicated
  metadata layouts remain unestablished. The known metadata bug is not repaired.
- Database line/branch coverage is 100%, but crash recovery, schema migrations,
  concurrency, and filesystem failures are not established by those percentages.
- Frontend interaction/accessibility/layout and live arXiv/LLM availability or
  actual model answer quality remain outside scope. A mock answer matching the
  saved answer verifies transport/storage, not independent scientific truth.
