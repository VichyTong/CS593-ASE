Tests added and what they establish

All eight are in tests/test_pdf_round1.py. No tests were corrected or removed.

1. test_pdf_file_size_boundary_is_accepted_and_one_extra_byte_is_rejected
   Exercises a real readable PDF padded to exactly 20 MiB (201, stored content
   and file hash correct) and 20 MiB + 1 byte (400, actionable size error, no
   paper/analysis record or uploads entry). No threshold/extractor is mocked.
   See the unit ambiguity below; this checks the configured binary convention.
2. test_oversized_multipart_request_returns_413_without_storage
   Exceeds the real 21 MiB transport cap, separately from the PDF file check.
   Checks HTTP 413, the size message, absent external calls, empty SQLite state,
   and no orphaned file. Multipart overhead is included by the test client.
3. test_page_count_accepts_one_and_150_and_rejects_zero_and_151
   Real 1- and 150-page PDFs retain every page number and its unique text;
   real 0- and 151-page PDFs are rejected with the page-count error and no
   storage. This covers both ends without hundreds of large page contents.
4. test_total_extracted_text_at_limit_and_one_character_either_side
   Two single-Tj pages total 999,999, 1,000,000, and 1,000,001 ASCII characters.
   The first two retain exact character counts and per-page text hashes; the
   last is rejected without storage. This tests the cumulative, not per-page,
   limit. Single-Tj fixture construction adds no unexpected line separator.
5. test_pdf_without_document_metadata_extracts_clear_title_byline_and_date
   The entire Info dictionary is absent and asserted absent with PdfReader.
   A 24 pt title, separate 12 pt two-person byline, affiliation, labeled 2024
   publication, explicit abstract, and introduction establish the gold values.
   Checks all metadata, source text, PDF bytes, and agreement of API and SQLite.
   Dataset year 2018 is not accepted as publication evidence. No provider runs.
6. test_multiline_prominent_title_is_not_misidentified_as_an_author
   Splits the same 24 pt title over two heading lines above the 12 pt byline.
   The intended title is the joined heading, and only the two byline people
   are authors. Checks real extraction and stored state; exposes the new bug.
7. test_absent_author_and_publication_year_are_not_invented
   Uses a no-Info PDF with title/abstract but no byline or publication evidence.
   Checks empty authors and null year despite the dataset year in prose,
   plus preserved title, abstract, PDF, and state. No provider runs.
8. test_optional_ai_metadata_failures_preserve_pdf_fallback_and_review_notice
   Four subtests fail at distinct boundaries: HTTP timeout, malformed JSON,
   valid JSON of the wrong shape, and an object with invalid metadata fields.
   Only HTTP post is mocked; the actual LLM client, JSON parsing, field
   validation, PDF extraction, route, and database run. Each case uploads
   successfully, returns an AI-unavailable review notice, retains PDF-derived
   title/authors/year/abstract and bytes/pages, saves no analysis, survives a
   fresh app instance, and deduplicates without another AI call. Assertions
   check the provider URL, model, timeout, dummy authorization, instructions,
   and evidence text. No arXiv request occurs for these identifier-free PDFs.

All five rejected boundary/request uploads passed the no-orphan assertions.
The four enrichment failures passed their fallback and persistence assertions.
All fixtures are synthesized on demand. File limits use legal comment padding;
large text uses known ASCII strings, avoiding slow heavyweight real-world PDFs.
See design-and-setup.txt for the pre-execution oracle reasoning and fixture
construction, which was not rewritten to accept the application's output.

Newly detected metadata defect

Detecting method:
test_pdf_round1.PDFMetadataTests.test_multiline_prominent_title_is_not_misidentified_as_an_author

Fixture evidence:
  24 pt: Reliable Storage for
  24 pt: Research Libraries
  12 pt: Dana Tester and Evan Researcher
  10 pt: Institute of Synthetic Studies
  10 pt: Published in the Synthetic Systems Conference 2024

Expected authors: ['Dana Tester', 'Evan Researcher']
Actual persisted/returned authors:
  ['Research Libraries', 'Dana Tester', 'Evan Researcher']

The joined title is correct. Assertions before the failure confirm success
status, readable text, a single exact stored PDF, page order, and agreement
between returned metadata and SQLite, so the spurious author is persisted,
not merely a display issue. The authors equality assertion then fails. Later
year/abstract gold assertions in that helper do not execute in this failing
case; the simple-layout case checks them separately.

Source inspection explains the result: extract_metadata first takes one title
line and scans following lines for author-like word counts (pdf_tools.py
64-77). The second title line has two words and is included as an author.
extract_pdf later joins the prominent title lines (41-52) but does not revisit
the author list. This explanation comes from code review and the actual
failure; no application patch or extra reproduction run was performed.

This is a metadata accuracy defect on a clearly specified synthetic layout,
not an incorrect fixture expectation. The README describes extraction as best
effort and permits user edits, so the finding should not be overstated as a
crash or a guarantee about arbitrary multi-line PDFs. Here the fixture roles
are explicit: 'Research Libraries' is a heading continuation, not a person.

Correctness review and ambiguity handling

No incorrect new expected value or fixture/setup failure was identified. This
is an agent review against the stated fixture roles and intended behavior, not
an independent human oracle certification. The failing metadata assertion must
not be 'fixed' by accepting title words as author names.

The binary meaning of '20 MB', inclusive-vs-strict error wording, priority among
multiple plausible publication dates, Unicode/NUL counting, exact policies for
unknown title placeholders, and general metadata accuracy guarantees remain
underspecified. This round records those issues and avoids choosing a date
priority, normalizing Unicode, or specifying unknown-title behavior from code.
It conditionally tests the current 20 MiB limit convention; that does not resolve
the decimal-vs-binary product requirement. The clear metadata cases have one
labeled publication year, explicit byline roles, and no conflicting title.

Assertions now address data and file state as well as statuses and metadata.
Per-case storage is fresh, so failed subtests do not poison later ones. Original
tests remain byte-identical and all previously passing outcomes are retained.
Some inherited limitations remain: message substring assertions, mocked model
answers, simplified HTTP responses, and homepage delivery checks. No fault was
seeded and no application mutation testing was performed.
